## 产品行为

- 默认角色画布穿透，操作按钮可点击；开启角色互动后画布接收点击，Escape 返回阅读。
- 默认闲置保留低帧率呼吸；开启「闲置时暂停动画」后，闲置 8 秒转为静帧。
- 更新：舞台随倍率同步缩放并受可视视口限制，模型按舞台重新适配；不再在固定画布内二次放大。顶部留白仍不承诺任意模型动作都不会越界。
- 自动情绪优先匹配明确语义的表情；无资源时仅使用小幅骨骼偏移。
- 口型失败只降级角色表现，不接管音频播放。

## 逐步实施细节

### 1. 配置边界与迁移

`LIVE2D_SCALE` 定义 0.4–2.5 的唯一范围。清洗函数只校验有限数字和位置；不会用旧模型缓存覆盖用户刚编辑的字段。缺少新字段的 v1 设置自动采用默认低帧率待机及空模型配置，无需清空原存储。

### 2. 单模型配置和删除

切换时先保存当前大小和灵敏度，再恢复目标模型配置；首次选择采用 1 倍默认值。更新函数仅接受当前模型的字段补丁，拒绝晚到的其他模型更新。删除使用同一清理函数同步处理页面配置与设置弹窗草稿。当前激活模型被删除后设为 null；删除其他模型不改变当前选择。

### 3. 音频解码

按 Blob 合并重复请求，最多两个任务进入解码。优先 OfflineAudioContext，失败时用独立实时 Context 回退，并在 finally 关闭。纯解码不请求 resume，也不连接音频输出。保留 Promise 错误给消费者降级，失败任务从 WeakMap 移除以允许重试。播放器仍是唯一音频输出方。

### 4. 渲染与资源生命周期

Canvas 为每个实例创建 private ticker，模型 autoUpdate=false；HIGH 优先级更新模型，再由 Pixi 正常渲染。每帧直接依据 audio.currentTime 采样口型。外部指针、语音状态、布局、情绪、动作及窗口重显都可唤醒，但隐藏/离开视口始终优先暂停。

运行控制器只保留一个闲置截止计时器，不常驻轮询。语音、用户动作启动或播放、拖动和姿态过渡保持活跃；自动 Idle 不阻止低帧率或节能静帧。用户动作强制 loop=false，播放中依据动作状态与优先级判断，避免把启动 Promise 当作完成通知。

卸载先停止 ticker、断开观察器与监听、移除 Canvas、销毁 Core/模型，再 await Assets.unload，最后销毁 renderer。该顺序避免 renderer 先销毁 Assets 所拥有的纹理。

### 5. 情绪与异步表情

初始化缓存参数索引及上下界，在 beforeModelUpdate 中给原生参数叠加小幅姿态；SDK 每帧加载回原生参数，避免偏移累积。按秒计算指数平滑，目标为零时逐渐放弃骨骼干预。表情先预加载再检查版本，操作串行化，更新目标时使旧 reserveExpressionIndex 失效。待机同时重置当前表情基线，避免引擎在动作结束后恢复旧表情。销毁后不再应用加载结果。

### 6. 阅读、互动与缩放

默认 Canvas 不命中 DOM 指针；工具按钮始终可达。互动开关开启后由原生 pointerup 调用 model.tap；不依赖 CSS hover 改变命中。工具栏的动作按钮与退出按钮支持键盘，Escape 退出并聚焦工具入口，关闭菜单使用 inert 防止隐藏控件被聚焦。

缩放先修改 Ref，最多每个动画帧更新一次局部预览，200ms 后通过函数式字段更新合并到父组件的最新设置。页面仅在本地设置加载完成后统一持久化，避免默认值覆盖已有存储，也不在 React 状态更新函数中执行存储副作用。切模型与收起时取消残留计时器和预览 RAF；主动收起及打开设置前提交当前大小。wheel 只在明确的大小控件上、Ctrl 且事件可取消时拦截，统一 pixel/line/page 单位。

### 7. 气泡、工具菜单与拖动

气泡通过 Portal 脱离移动端 backdrop-filter 的定位参照影响。ResizeObserver 测量内容和舞台；VisualViewport 的 resize/scroll 负责可视范围变化。先选择上下空间，再夹取水平位置，尾巴对齐舞台中心并避开圆角。定位外层与出场动画内层分离。

工具菜单也根据可视视口夹取位置并允许内部滚动。拖拽结束时仅在距左右边缘 48px 内吸附到 16px 留白，然后再次执行视口夹取；桌面与移动位置仍独立保存。

### 8. 分析事件

在本地解析、模型解析和模型校正的真实开始点分配请求编号；仅当前编号可发布成功、失败或取消。重试创建新编号，编辑原文、改设置、改语言和用户取消立即失效旧事件。缓存恢复不创建成功事件。Widget 根据事件原始时间计算剩余反馈时长，避免模型加载或重挂载后重新庆祝 3.5 秒。

### 9. 验证与后续边界

自动测试验证纯状态控制、异步竞争和数据隔离，Chrome 验证真实渲染、资源释放和窄屏交互。仍需 Safari/iOS 与更多模型实测；不以 mock 测试或单一模型证明全浏览器兼容，也不把暂停渲染等同于整页功耗归零。未运行生产打包与部署。


## 2026-10-20：图标、尺寸、阻尼与画质迭代

上一轮六项需求已实现：九点拖动 SVG；手掌/书本互动切换 SVG；人物头像替换星形；舞台和画布随倍率增长并保持在视口内；自定义平滑开关、单选、按钮；主题适配的胶囊轨道和滚动条底色。Lucide 来源与许可保存在 NOTICE 和 LICENSES/Lucide-LICENSE.txt。

新增交互使用现有 Motion 依赖，无新增安装包。`Live2DSlider` 统一三个设置滑杆及快捷大小滑杆。数值与填充即时更新，可见滑块用 stiffness=700、damping=36、mass=0.4 跟随；微反馈独立使用 stiffness=900、damping=22、mass=0.3，常规约 0.7px，端点约 1.2px，70ms 内不重复触发。`Live2DScrollFeedback` 覆盖设置内容、溢出菜单和长错误说明，保留原生 wheel/touch 内容滚动，滑块加弹簧和约 0.65px 侧向反馈。内容和 ARIA 值不等待动画；支持拖动、方向键、Home/End、PageUp/PageDown。Portal 菜单滚动条不会触发点击外部关闭。减少动态效果偏好会停用位移反馈。

Cubism 遮罩从默认小图集提升到 512/1024 分档，单实例只升级不反复降级分配。实际浏览器测试发现 SDK setClippingMaskBufferSize 重建管理器后不会保留 GL 上下文，现通过 startUp 立即重绑；新增回归用例覆盖首次和运行中升级、上下文复位以及缓冲区复用。

验证：全量 npm test、TypeScript、定向 ESLint、git diff --check 通过。运行与画质测试共 13 项。Chrome Retina 实测最小舞台 96×144 对应 192×288 像素，2.5 倍舞台 550×741 对应 1100×1482 像素；遮罩实时从 512 升至 1024 后角色持续绘制，没有新增遮罩异常。滑杆数值从 2.0 即时变为 1.9，可见滑块先经过 99.1482%，随后准确收敛到 93.3333%，微偏移回到 none。320×260 低高度视口下角色菜单滚动条保持可达，End 滚动到 100%，操作时菜单保持展开。

## 2026-10-20：角色附近误选文字与滑杆刻线修复

复现：阅读模式下 Canvas 为 pointer-events:none。在角色头部双击会让浏览器选中附近「寄り」，在身体位置双击会选中输入区装饰提示「粘贴」。事件实际命中的是页面 main 的空白部分，不是对应文本框；这是浏览器对空白点击应用最近文本行选区的行为。

修复：仅在舞台覆盖区域内、指针实际命中空白时阻止 pointerdown/mousedown 的默认选区行为；正文文字用 Range.getClientRects 验证实际命中，输入、链接、按钮等真实控件继续穿透。舞台外、触屏滚动、右键及显式 Shift 扩展选区均保持原行为。互动模式同时抑制 Canvas 的原生选区，按下与释放按 pointerId 配对，取消或移动超过 6px 不触发角色 tap；事件监听随模型销毁清理。没有全局禁用正文选择，也没有主动清空用户已有选区。

滑杆修复：移除先前加入的独立即时位置刻线，把滑块从轨道内部移至独立覆盖层，明确轨道 z=0、圆球 z=1、透明原生输入 z=2，并隔离叠层。圆球使用不透明填充，保留即时数值/轨道填充、弹簧跟随和微反馈，避免位置刻线与运动中的圆球重叠。

浏览器验收：阅读/互动两种模式分别连续双击头部、身体、腿部，六组操作选区均为空；原先相同坐标可复现「寄り」「粘贴」。页面正常文字仍可双击选中「可能」。设置滑杆快速往返拖动后没有刻线节点或线条，数值正常变化；测试草稿已放弃，原设置保持不变。新增选择保护回归测试，覆盖实际正文/控件、空白、舞台外、触屏、右键和 Shift 情况。Live2D 测试现为 14 项；全量 npm test、TypeScript、定向 ESLint 和 git diff --check 通过。Safari/iOS 的原生选区行为尚未实机验证。


## 2026-10-20：滑杆填充与圆球同帧同步

上一次去除刻线后仍有观感问题：填充使用即时 progress，而圆球的水平 left 仍由 useSpring 延后更新，所以拖动时会出现线条领先、圆球追赶。现移除水平位置弹簧，让填充 width 与圆球 left 在同一次 React 提交中使用完全相同的百分比；弹簧只负责按压缩放和小幅垂直反馈，不延迟用户操纵的位置。

浏览器快速右/左/右拖动实测值 1.9、0.6、1.5，填充和圆球分别同时处于 93.3333%、6.66667%、66.6667%，三次填充终点与圆球中心偏差均为 0px。设置中的三条滑杆以及共享组件的快捷大小滑杆均采用此行为。测试草稿已放弃，用户原设置保留。TypeScript、定向 ESLint、Live2D 14 项测试和 git diff --check 通过。

## 2026-10-20：短句跟读气泡与共用高亮

根据用户选择，当前短句先完整显示，朗读到的词高亮，下一句开始时切换；气泡与页面原文使用同一个词位置。原实现整段原文直接进入气泡，最大高度接近整个视口；现按句末标点切分，过长短句优先在逗号或空白处切分，无标点文本也以 42 个字素为基础上限分段。句末标点与闭引号留在前一页，段间空白不单独成页；显示时去除页首尾空白但原文偏移不变。气泡宽度 260px、基础高度约三行、最高 132px，同时受 VisualViewport 实际范围限制。切词不重播入场动画。

新增 speechReading 保存原文 UTF-16 范围，保留服务端原始词边界，避免没有解析 tokens 时丢失时间戳。音频时间始终读取 currentTime，暂停、进度回退和重播不会依赖固定文字播放定时器。没有官方边界时使用捕获的日语读音与总时长估算；仅在 token 拼接与原文一致时采用该读音。系统语音透传 boundary/pause/resume 事件，不支持边界的系统音色使用近似时轴。浏览器接口依据：[currentTime](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/currentTime)、[SpeechSynthesisEvent](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisEvent)。

speechReadingStore 使用一个订阅时钟，页面和气泡共用；每帧读时间但只在词位置或状态变化时通知 React。页面隐藏时取消帧循环，重新显示立即读取音频真实位置；最后一个消费者卸载时清理音频事件、store 订阅和动画帧。旧会话的边界与结束回调不能修改新会话。页面使用原文范围映射到已有 playing-cue 样式，音频未提供真实时间戳时不宣称精确逐词同步。

## 2026-10-20：高亮交叉淡化与朗读气泡退场

切词卡顿有两处结构性原因：page.tsx 订阅了逐词位置，导致每次切词重新计算并协调整页及长文；气泡按当前词拆分文本/mark，每次替换文字节点，旧高亮立即撤掉。现将页面订阅下移至 SpeechReadingHighlight，只修改前后两个显示单元的 data-reading-current，不改变词节点和选择状态，也支持阅读视图中组合词的范围。React 回归测试证明连续边界事件期间句子父组件只渲染一次，卸载清理高亮和时钟。

正文采用稳定伪元素层，通过 120ms opacity 交叉淡化；主体文字颜色和几何尺寸保持稳定，注音颜色也用短过渡适配高亮底色。气泡使用稳定的字素片段和 120ms background-color 过渡，既保留组合字符和 emoji，又能精确显示服务端词范围，避免 Intl 分词边界把相邻助词一并高亮。换句的两个内容层短暂交叉淡化；没有布局位移或每词弹跳。减少动态效果时高亮过渡缩短为 80ms。

AnimatePresence 保留结束会话的气泡，整个 Portal 锚点（包括尾巴）以 150ms opacity 淡出后移除。退出期间保留最后一次匹配的 reading，避免 store 清空后跳回第一句再淡出。新会话按独立 key 处理，暂停不触发退场。采用已有 Motion 依赖，无新增依赖；接口依据：[AnimatePresence 官方文档](https://motion.dev/docs/react-animate-presence)。

## 2026-10-20：音频时间驱动的词内扫光试用

按用户同意的第一阶段方案加入连续词内进度与柔边扫光，没有增加 PCHIP、弹簧追踪或歌词播放器依赖。词内进度直接为 clamp((audio.currentTime - startTime) / (endTime - startTime), 0, 1)，在静音间隔夹取为 1，回退时直接按新的媒体时间计算，不累加动画时间、不缓动主时间轴。仅有边界事件、缺少词持续时间的系统音色采用整词高亮，不虚构精确进度；只有估算时轴的音频仍为近似跟读。
