# 今日一句

第一阶段采用“后台联网补充候选池，用户点击即时换句”。首页立即显示当天最后选句；没有选句时，从已缓存候选或内置句库选择。网络请求只更新候选池，不修改当前显示内容。桌面版使用随应用启动的 Next.js API，不依赖账号或公共网站部署。

## 即时选句

标题旁的「换一句」保留固定水平间距，标题保留箭头动画。每次点击同步选择一个新句子，优先使用当前语言有译文的在线候选，没有在线候选时立即使用本地句库。断网时也可使用之前缓存的在线候选。点击不会等待网络、不显示网络等待状态、不触发模型调用。

同一事件内的重复点击合并；不同次点击各选一句。后台请求进行中、失败或超时时按钮仍可使用。新候选只供下一次选句使用，后台完成不会再次切换当前句子。

## 候选池与持久化

`japaneseAnalyzer:dailyPool:v1` 保存当前选句、最多 120 条在线候选、近期记录以及各语言的同步时间和失败退避时间。候选在加入时洗牌，消费后移除；按原文和来源 ID 排除最近 30 天内最多 200 条已选记录，并排除当前原文。本地选句也记入原文去重历史。

未使用的在线候选最多保留 7 天，跨日可继续使用；日期沿用日本时间，当天最后选句会在重启或刷新后保留。日本零点、窗口恢复焦点和可见性变化时检查日期。旧版 `japaneseAnalyzer:dailySentence:v2` 的当前在线句子和近期记录自动迁入新池，后续以新池为准，避免恢复旧的在线缓存。

存储损坏时安全回退；写入失败时仍在内存中保留候选、已消费记录和当前选句，语言切换不会恢复旧句。无法写入本机存储时，退出页面后的持久化无法保证。

内置 60 条项目编写的例句，每条包含分词、读音及简体中文、繁体中文、英语、韩语译文。本地索引和剩余顺序保存在 `japaneseAnalyzer:dailyDeck:v1`，使用 Fisher–Yates 洗牌，一轮内不重复，轮次交界不立即重复。

## 后台同步与退避

页面启动、恢复联网、窗口聚焦或用户消费候选后检查补充条件。单个组件同一时间只有一个后台请求，点击换句不会取消或重建正在进行的补充请求。

候选数不超过 3 条时，距上次成功同步至少 15 分钟可补充；候选充足时，24 小时后检查更新。失败后依次等待 15 分钟、30 分钟、1 小时，最长 6 小时再尝试。等待时间持久化，刷新页面、快速点击或反复触发联网事件都不会绕过退避。离线时暂停联网，恢复后仍遵守退避。

后台请求使用 `/api/daily-sentence?locale=...&refresh=1`。服务端在 10 秒内复用批次；较慢但尚未完成的请求继续合并。服务端等待上游最多 15 秒，浏览器后台请求上限 18 秒，统一在 `app/utils/dailySentencePolicy.ts` 配置。这些超时不会延迟用户选句。具体失败原因保留在服务端诊断日志，页面继续使用已有句子。

跨日、语言切换和组件卸载会取消旧后台请求；即使旧请求稍后返回，也不能写入新池或改变显示。

## 在线来源与许可

使用 [Tatoeba API v1](https://api.tatoeba.org/openapi) 的 `/v1/sentences`，无须 API Key。每次最多取 12 条候选，要求日文、母语贡献者、非孤立、未标记为未审核，并请求关联的直接译文。服务端校验长度、单句格式、链接或标记、许可及重复内容。母语状态为贡献者自报，不能替代内容审校。

只请求固定公共端点，不发送用户原文、密钥或模型设置。在线句子不自动调用 AI 或加载分词引擎，只显示原文和实际已有的直接译文。中文保留 Hans/Hant 文字体系；没有当前语言译文时隐藏译文，不使用其他语言替代。

原句和显示的译文分别提供 Tatoeba 句子页及许可链接，接受 `CC BY 2.0 FR`、`CC0 1.0`，保留未经改写的原文和译文。参见 [官方语料使用说明](https://en.wiki.tatoeba.org/articles/show/using-the-tatoeba-corpus)。

下一阶段可从 [Tatoeba 官方批量导出](https://tatoeba.org/en/downloads) 生成经过筛选和审校的静态句包，随应用提供基础版本，联网后台检查更新。当前阶段不依赖新增 CDN 或公共部署，也不直接接入许可未明确的名言接口。
