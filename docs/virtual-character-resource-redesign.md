# 虚拟角色资源管理重设计提案

调研日期：2026-10-21。状态：方案，尚未修改产品页面与运行逻辑。

## 目标与范围

覆盖选择／导入角色、动作与表情浏览、预览、改名、待机播放、部位点击、自定义区域、快捷键、伴学反馈、试用、保存及异常恢复。聊天、朗读气泡和正文跟读维持现有流程。

用户无需理解 Idle、TapBody、HitArea、动作优先级或 JSON。一次任务应回答三个问题：它是什么效果、什么时候使用、是否已经生效。

技术沿用 Next.js 15、React 19、现有 CSS 变量／nd-input／Lucide SVG、Pixi 8 和现有 Live2D 引擎。不以替换渲染器解决信息架构问题。

## 新的信息架构

设置中的入口仍叫“虚拟角色服务”。入口显示当前角色卡片、启用开关和“管理角色”按钮。

进入管理后，使用同一设置面板内的完整工作台，暂时收起全局设置导航，顶部提供“返回设置”和角色切换。不要再打开第二层模态框。

工作台只有三个主标签：

1. **角色**：导入／切换、大小、位置、透明度、口型、视线和性能；资源数量与加载诊断折叠显示。
2. **动作与表情**：看效果、改名、查看已有用途、添加用途。
3. **互动设置**：平时动作、点击部位、快捷键、伴学反馈；显示现有规则并直接试用。

原“模型能力”撤销独立入口，转化为互动规则中的实际状态；原“动作资源”只在“动作与表情”呈现；原“管理动作”由整个工作台承接。

## 动作与表情页面

宽屏采用两栏：左侧资源目录，右侧固定预览及当前资源操作。右侧内部将主操作放在预览下，详细文件信息收在折叠项。较窄设置面板和移动端改为列表 → 资源详情两级导航，返回保持筛选和滚动位置，不硬塞三栏。

目录工具：搜索名称（同时匹配原始名、文件名）、动作／表情切换、用途筛选（全部／待机／点击／快捷键／伴学／尚未使用）。空类型仍显示计数，例如“表情 0”，点击后说明“此模型未包含表情文件”。

每一行只呈现：

- 自定义名称或默认名称。
- 资源类型与真实用途，例如“动作 · 待机随机播放”“动作 · 点击身体”“表情 · 分析成功”。用途超过一项显示数量，详情完整展开。
- 显式“预览”按钮，不把行点击变成隐式播放。

行点击只选择。预览按钮就地启动；键盘 Enter 激活所聚焦按钮。取消整行重复两次名称。播放状态独立显示“加载中／预览中／已结束／失败”，不和用途拼成难理解的状态串。

右侧包括资源名称、当前用途、预览一次／停止／恢复默认，以及“用于…”按钮。快速切换上一个／下一个保留在紧凑工具栏。动作按实际完成事件结束；预览默认静音、不循环。可选循环仅影响本次预览，不改变待机设置。

“用于…”打开就地配置面板，列出平时自动播放、点击角色部位、键盘快捷键、伴学反馈。选择用途时继续保留当前资源，避免再从长下拉列表重新选择。

默认名称只能说明来源：Idle 来源显示“待机动作 1”，附“来自模型的待机组，具体效果请预览”；未知来源显示“未命名动作 1”。不把编号文件猜成点头／害羞。用户可以改成任何名称，底层资源类型与 ID 不变。表情也可能是换装、配件或显示开关，说明中不要承诺它只影响脸部。

## 互动设置页面

默认展示易读规则，而非先展示技术性的两个下拉框。

| 分类 | 规则示例 | 操作 |
| --- | --- | --- |
| 平时动作 | 无人操作时 → 从 3 个动作中随机播放 | 选择动作、播放方式、试用 |
| 点击部位 | 轻点身体 → 身体互动 1 | 修改、试用、停用 |
| 点击部位 | 轻点头部 → 尚未设置 | 添加区域／选择动作 |
| 快捷键 | 角色获得焦点后，按 A → 左右张望 | 修改、录入、试用、删除 |
| 伴学反馈 | 分析成功 → 开心表情，3.5 秒后恢复 | 修改、模拟成功、停用 |

每条规则显示“来自模型默认／自动匹配／你设置的”，以及当前是否生效。由有效配置计算的结果统一供资源页和互动页使用，避免一边写自动、一边写未绑定。

自动匹配是可解释建议，不等于资源已成功加载。新导入后展示“已找到身体点击动作”“未提供独立头部区域”等具体结果。现有明确自动规则迁移后继续工作；不因为重设计关闭用户已有互动。编号不明的资源不自动猜测用途。

### 平时动作

- 三种模式：使用模型默认、选择动作、关闭动作播放。
- 自选可选一个或多个 motion：单项重复；多项支持随机／顺序，随机尽量避免连续重复。
- 执行频率由动作完成与所设间隔驱动，不能按固定间隔截断长动作。首版间隔默认沿用连续待机体验，个性化间隔放在高级项。
- 配置中的“使用模型默认”和用户勾选清单互斥，避免双调度器同时播放。
- 关闭 motion 不同时关闭眨眼、呼吸或视线；这些仍由角色设置控制。
- 表情不作为待机动画循环。可在表情详情设置为默认外观，明确它与轮播动作的区别。
- 开启“闲置时暂停动画”时显示就地提示：待机播放将于闲置 8 秒后暂停，唤醒后恢复。

### 部位与自定义区域

点击“添加点击互动”后，先选现有部位或“自己画区域”，再选动作／表情，最后试用。

编辑器明确三个模式：浏览预览、编辑区域、试用互动。编辑时拖动创建／移动矩形，试用时轻点触发，两个模式的指针行为不混用。设置中的舞台不移动桌面角色。

原生区域显示“模型提供”；自定义区域显示“你添加的”。缺少头部时提供画区域入口，不谎称没有办法配置；但必须提示“添加区域不会生成新动作，仍需选择模型已有资源”。

删除按钮位于对应区域行；支持撤销。重叠时提供“此处将触发：头部 → …”命中反馈；优先级在高级设置调整，默认小范围区域优先需谨慎迁移，旧区域继续保留原有显式顺序。禁用区域和删除区域不同：禁用仍阻断此区域互动，删除后允许下层命中，确认文案明确区别。

### 快捷键

录入后立即检测冲突，显示冲突规则并提供跳转或显式替换。默认仍只在角色获得焦点时生效，输入文字时不触发。试用舞台获得焦点后能按键验证；读屏／键盘也可用“试用”按钮，无需鼠标绘制才能完成配置。

### 伴学反馈

用“开始分析／分析成功／分析失败”命名实际事件。每行旁边有模拟按钮；模拟只改变预览，不发送解析请求、聊天请求或朗读请求。

动作默认单次播放，播放完回待机；思考动作可在分析期间重复并于任务结束退出。表情提供事件结束后恢复／指定秒数恢复，成功与失败默认 3.5 秒。取消分析及时恢复，缓存恢复不触发成功庆祝。

## 表情的专属操作

资源页提供“试用表情”“恢复默认”和激活状态。配置用途时选择自动恢复或再次触发关闭。首版默认同一时刻只有一个临时表情；新临时表情替换旧临时表情，结束恢复用户选定默认外观。多表情叠加涉及参数冲突，留作高级功能，不在首版假装通用兼容。

默认外观也是模型局部配置；预览时切换不自动持久化。短期伴学表情结束必须回到用户默认外观，而不是无条件清空所有外观配置。

## 以“自然待机 1”为例的新流程

1. 打开“动作与表情”，点击“待机动作 1”行上的“预览”。
2. 观察效果，可自定义名称。未观察前不预填“左右张望”等语义。
3. 点击“用于…” → “平时自动播放”。
4. 选择“只播放此动作”或加入现有清单，清楚显示将替换／追加哪些动作。
5. 点击“试用待机”，预览使用草稿配置连续播放；无需先保存。
6. 点击底部“保存更改”，提示“已应用到 Hiyori：平时播放 1 个动作”。

若想点击身体触发，同一个“用于…”选择“点击角色部位” → “身体”。若已有规则，明确显示被替换项并确认。资源详情随后同时显示待机和点击身体两项用途，改名不影响任何绑定。

## 保存、错误与资源管理

- 配置修改为工作台草稿，预览与试用读取草稿；桌面角色只在“保存更改”后更新。页脚固定显示修改计数、取消／保存，避免再叠加第二套全局保存按钮。
- 切换工作台标签或选中其他角色保留各模型草稿；退出存在修改时选择保存／放弃／继续编辑。取消停止预览、清理临时表情与计时器。
- 文件导入是独立资源操作：导入成功提示“已保存到此设备”，即使取消配置草稿也不删除导入文件。移除角色单独确认资源和配置删除范围，避免与“取消设置”语义混淆。
- “移除用途”不删除原始 motion／expression 文件；首版不提供单文件物理删除。保留原 ZIP 和稳定 ID，避免破坏模型引用。
- 资源状态分别是已发现／未验证、可播放、加载失败。只有试播或验证成功才能标为可播放。失败提供重试、原始文件位置和重新导入入口；一个动作失败不锁死整个目录。
- 资源缺失保留配置与用户命名，明确显示“资源缺失，暂不执行”，不得静默改播别的动作。
- 无模型：导入入口与包格式说明；无动作：仍可使用模型本身的呼吸／眨眼等能力；无表情：说明缺少文件并切回动作；无搜索结果：提供清除筛选。
- 全语言同步交付；自定义名称不翻译，系统用途／状态按语言切换，原始文件名保留于详情与搜索。

## 视觉与可访问性约束

沿用现有紫色强调色和单层 nd-input 焦点效果。按钮以 SVG 加文字表达动作，播放和已应用状态不要只用颜色。普通列表行使用轻量分隔，不为每个资源套多重描边卡片。

桌面目录与详情各只有一个明确滚动区域；页脚不遮挡内容，预览主操作保持可见。320px／200% 缩放切换为逐页详情，避免嵌套横向滚动。资源列表过长时才启用现有虚拟列表工具，不同时创建多份 WebGL 预览。

所有按钮和字段具备名称、可见键盘焦点；热区有名称及数字输入替代拖动；试用结果用简短状态播报，角色动画本身不连续播报。高频选择、筛选与拖动即时反馈，不引入弹簧位置延迟；减少动态效果时停用位移／缩放动画。

## 技术实施顺序与验收

### 1. 统一资源与用途数据

保留现有稳定资源 ID 和单模型隔离。将不可变资源目录、可保存配置、临时播放状态分开。新增版本化配置迁移，增加待机清单和表情恢复策略；已有别名、区域、快捷键、禁用规则、缺失资源绑定全部保留。自动来源与最终有效用途由统一解析函数产出。

验收：升级前后既有点击／按键不变，显示用途与解析结果一致；不能把未加载资源宣称为可播放。

### 2. 搭建工作台与资源页

拆分现有 Live2DActionEditor 长表单，建立统一预览控制器、目录、资源详情和用途面板；Live2DSettings 只负责入口与角色基础设置。先实现桌面／窄屏完整任务流程，再完善视觉状态。

验收：无需滚过长表单即可预览并为所选资源设置用途；资源和表情空状态明确，搜索与语言切换不丢草稿。

### 3. 重建互动配置和试用

规则卡片、资源选择器、区域编辑／试用模式、快捷键冲突检测和模拟伴学事件共用有效规则解析。资源页与互动页修改同一份草稿，不维护两套绑定。

验收：可从资源选用途，也可从事件选资源；两条路径保存后结果相同；试用不触发真实业务请求。

### 4. 落地待机与表情生命周期

在运行层添加单一待机调度策略，不仅修改组名或 UI 勾选。动作完成后再调度；用户新指令替换旧指令，手动互动优先于伴学反馈、伴学反馈优先于待机。说话口型为独立参数驱动，不因为抢占动作停止语音。

清除所有迟到加载、已取消请求、过期恢复计时器；区分预览与桌面实例。收起、停用、切换模型和页面隐藏时按既有节能策略暂停／销毁。手动动作结束恢复有效默认外观与待机清单。

验收：只选待机 1 时不再随机播放 2–9；多项轮播不截断动作；成功／失败表情按配置恢复；闲置暂停设置与待机配置相互解释且行为一致。

### 5. 迁移、可访问性及回归

运行类型检查、相关 ESLint、live2dActions／live2dRuntime／companion 与语言字典检查；补测真实决策行为（用途派生、配置迁移、调度取消、恢复默认、冲突与删除撤销），不为样式写镜像测试。

浏览器验收至少覆盖 Hiyori、一个含表情的可用模型、缺少 HitArea／缺资源场景；若没有合法可用含表情资产，必须明确该实机项目未验证，不能仅凭 mock 宣称兼容。检查 320px、200% 缩放、键盘全流程、减少动态效果、四种语言、浅／深主题及焦点／对比度。

最终任务验收：首次用户能找到一个动作、观察效果、改名、设为唯一待机、绑定身体、试用、保存，之后能看懂它的全部用途，并能取消其中一项而不影响另一项。

配置导出／导入、批量命名、多表情组合、独立资源导入和高级参数编辑后续再做，不阻塞首版主流程。
